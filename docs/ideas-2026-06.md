# Ideas — June 2026

A curated, fun-but-actionable idea pile for chota and its agent, dated 2026-06-24. Generated by a four-angle fan-out (print formats & rituals · agent personality & proactivity · physical box play · family-utility & learning), then curated down hard. **This is a shortlist, not a backlog** — only ideas that fit the north star in [`next.md`](next.md) survived: print-first, dial-driven, kid-safe-by-construction, ambient-when-closed, no-glow-at-night. The unfiltered pile and prior research still live in [`inspiration.md`](inspiration.md), [`tools.md`](tools.md) §Future, and [`audit-2026-05.md`](audit-2026-05.md).

Curation lens applied throughout: **press → paper-in-hand is the ritual** (pre-generate overnight, serve cached <5s — only `story` generates live, where the wait is theater); **paper-as-object beats paper-as-memo** (a thing you do something with survives; a thing you read once dies by week 3); **the agent's restraint is a feature** (a memo is spam, a gift is remembered); **the box should make a kid _want_ to walk up to it.**

## Top 10 — would actually pursue

### 1. Secret Mission (new WHAT-dial position)

**Pitch:** WHO dial × `mission` → one silly-but-achievable dare for the day, tear-off, kid's name big at the top ("Tell someone a fact about penguins"; "Do 10 jumps before lunch"; "Draw with your wrong hand"). The paper is the permission slip.
**Why it fits:** Personalised by the WHO dial, kid-safe (dial-constrained prompt), and it's an _object the kid acts on_, not info. Trivial to pre-generate + cache overnight.
**Effort:** S · **Leans on:** existing print pipeline + a short-text composer + Haiku pre-gen from kid interests in config (new WHAT position, small new composer).
**First step:** add a `mission` composer that prints one cached line per kid; seed prompts from `chota.config.ts` interests.

### 2. Chore Ticket (tear-off contract)

**Pitch:** WHO × `chore` → a tear-off slip with one chore, a checkbox row, and a "claim your reward" line. Done = deposit the slip in a jar.
**Why it fits:** Turns the receipt into a contract, not a list. The physical hand-off (kid → parent → jar) is the ritual. TickTick already holds the chores.
**Effort:** S · **Leans on:** `ticktick` tool + `chores.ts` rotation + existing ESC-POS text format (no new tool).
**First step:** new composer that renders today's chore for the dialed kid with a checkbox + tear line.

### 3. Bus Anxiety Needle

**Pitch:** The analog needle meter sweeps from "chill" to "RUN" as the next bus approaches — not a number, a _feeling_ a kid reads across the kitchen.
**Why it fits:** The strongest use of hardware we already bought; pure ambient signal, zero glow, kid-legible without literacy. Makes the box useful while _closed_.
**Effort:** S · **Leans on:** existing needle PWM + `bus` tool — just map minutes-remaining → 0–100% duty cycle (Pico firmware + one `/api/status/needle` endpoint).
**First step:** ship `/api/status/needle` returning minutes-to-next-accepted-bus; Pico polls + drives the meter.

### 4. The Quiet Witness (agent milestone line)

**Pitch:** The agent's closing line on the brief occasionally — and only occasionally — marks a milestone it noticed in memory (100th morning print, first day back after holidays, a birthday week). Not announced. Just _there_ for the family to find.
**Why it fits:** This is the difference between the agent being a memo and being a member of the family. Lands directly in the already-planned closing-line slot; pairs with **Earned Silence** (#12) so it never becomes filler.
**Effort:** S · **Leans on:** the planned agent closing-line job + memory JSONL `milestone` tags from the dreaming pass (no new tool).
**First step:** define the closing-line job; have it print the milestone line only when the dreaming pass flagged one for today, else nothing.

### 5. Match Day Note (proactive printed insert)

**Pitch:** The night before a kid's sport/event (from calendar or Sentral), the agent queues a tiny printed insert the kid finds tucked under their morning brief. "Go get them."
**Why it fits:** Memory-driven proactivity that's a _gift, not a nudge_. Reuses the print pipeline; the surprise is the payload. The canonical "remembered it's Zia's match day" moment.
**Effort:** S · **Leans on:** `calendar` + `sentral` + print pipeline + a small `printInsert()` composer (new composer, existing tools).
**First step:** evening job scans tomorrow's events for a sport/performance match → queues a one-line insert ahead of the 06:45 batch.

### 6. Tomorrow Gear-Check (the print consumer of the activities map)

**Pitch:** Evening print: "Tomorrow: swimming (Kid2 — goggles, towel, cap). Kid1 soccer (boots, shin guards)." Kills the morning scramble.
**Why it fits:** The `activities → gear` mapping already exists in `chota.config.ts`; this is just the print render of data we already have. Nearly free, pure logistics, never dies.
**Effort:** S · **Leans on:** existing activities config + `calendar` for tomorrow's events (no new tool — folds into the planned tomorrow-prep print).
**First step:** join tomorrow's calendar events to `activities[].gear` and render a gear block on the evening sheet.

### 7. Meal-Plan Strip

**Pitch:** Today's + tomorrow's dinner, read from a dedicated TickTick list. "Tonight: pasta. Tomorrow: BBQ — defrost chicken." The "defrost chicken" line is a real action.
**Why it fits:** Kills the 4pm "what's for dinner?" panic; parents maintain the list, kids read it. Logistics, so it survives. Reuses the `ticktick` read path entirely.
**Effort:** S · **Leans on:** `ticktick` tool reading a named meal-plan list (no new code — a list-name convention in config).
**First step:** add a `mealplan` list name to config; render its top two entries on the brief.

### 8. Toggles as Print Modifiers

**Pitch:** The 3 mini SPDT toggles become opt-in flags for _tomorrow's_ brief — "add jokes," "add puzzle," "add weather sparkline." Set your toggles before bed; the 06:45 honours them. A bedtime family ritual.
**Why it fits:** Gives the already-mounted toggles a real job inside the no-touchscreen ethos, and personalises the unattended morning print without any screen. Composers mostly exist.
**Effort:** M · **Leans on:** existing print composers + Pico reads toggle state into the `POST /api/print/[kind]` body; server includes/skips sections (new flag plumbing, reused composers).
**First step:** define 3 toggle→section flags; thread them through the print payload and gate the optional composers.

### 9. Story Mode under the Missile Switch (the dial-combination feature, dressed up)

**Pitch:** Flip the missile-switch cover, throw the switch → the box enters Story Mode: WHO dial = hero, WHAT dial = genre, PRINT → Haiku writes a one-page story starring the kid, with block-art borders. The deck screen runs the generation animation while it writes.
**Why it fits:** This is the planned `story` format given a _ceremony_. The missile switch makes it feel like unlocking something; the 5–15s wait is theater, not lag (the one format allowed to generate live). Kid-safe — dials constrain the whole prompt space.
**Effort:** L · **Leans on:** the planned `story` composer + `POST /api/print/story` + missile toggle + deck-screen `/panel` animation (new: thermal block-art formatter, mode wiring).
**First step:** ship `story` against the existing dials first; add the missile-switch "mode gate" + deck animation as the ceremony layer.

### 10. Star Chart / Week Wrap (the keep-it-on-the-fridge weekly pair)

**Pitch:** Friday: WHO × `week` prints a 7-column star grid for next week's goal (reading, practice — per-kid from config), to tick off by hand. Saturday's family sheet gets a **Week Wrap**: 3 things that happened (calendar + completed TickTick), one number ("walked 4 days"), one best moment.
**Why it fits:** Closes the weekly loop with two fridge-objects, not screens. The grid is a physical streak tracker; the wrap is gentle nostalgia. Saturday cron slot already exists.
**Effort:** S (chart) / M (wrap) · **Leans on:** new ESC-POS grid renderer + a `weeklyGoal` config field (chart); `calendar` + `ticktick` + Saturday cron (wrap).
**First step:** ship the Star Chart grid first (static, no AI); layer the Week Wrap onto the existing weekend sheet.

## Quick wins (S-effort, high-delight, mostly reuse)

- **Earned Silence + The One-Word Reply** — codify in `soul.md`: when the agent has nothing genuinely worth saying, the closing line is blank/an em-dash, and a "thanks" over Telegram gets a one-word reply. Restraint as personality; it's a rule, not code. _(soul.md + system prompt; the dreaming pass sets a `low_signal` day flag.)_
- **Print Countdown Strobe** — press the arcade button → the 25 LEDs chase the perimeter while the job runs, all flash once when paper pops. The button _is_ the theater. _(Pico listens to print start/done SSE events.)_
- **Idle Heartbeat** — closed box, one LED breathes on a 3s cycle; from 06:44 the LEDs light one-by-one until the 06:45 fires. Night-safe (no screen glow), runs standalone on the Pico. _(Pure Pico firmware, no server round-trip.)_
- **Lid Theater Fanfare** — opening the lid wakes the deck screen with a short reveal (gears/paper-curl) + a 3-LED sweep before settling on the clock. Makes opening feel like a music box. _(lid-detect → SSE → `/panel` animation.)_
- **Countdown Ticker** — WHO × `countdown` → one fat number: "3 sleeps until Kid2's birthday," "14 days to school holidays." Peel off, stick on the door. _(config `namedDates[]` + date math + big ESC-POS text.)_
- **Mad Libs Slip** — WHO × `madlibs` → a fill-in-the-blank skeleton (VERB/ANIMAL/FOOD), kid fills it with the pencil from the groove, reads it aloud. Static template library, zero AI wait. _(20–30 static templates + random daily pick.)_
- **UV + Surf line** — Sydney-specific one-liner in the weather block: UV index ("UV 11 — sunscreen non-negotiable"), beach-viable flag, optional surf height on weekends. _(Google weather already returns UV; surf is an optional config + API.)_
- **Sport Results Digest** — pre-game/post-game one-liner for the family's named NRL/AFL/cricket teams. _(`google_search` or a sports API + team names in config + a ~11pm cron.)_ _(Flagged: dies if the team has a bad season — keep it one line, easy to drop.)_

## Big swings (L-effort, distinctive)

- **Story Mode under the missile switch** (Top 10 #9) — the flagship "this box is magic" feature; ceremony + live generation + deck animation.
- **Treasure Hunt** — WHO × `hunt` → 4–6 sequential clues themed to the kid, last one names the hiding spot; parent pre-stashes a prize. The receipt _is_ the game. Generate on parent request (admin trigger), not cron. _(ToolLoopAgent + Haiku + new composer.)_
- **The Crystallized Ritual** — when the family asks the agent the same thing 3+ times over Telegram, the dreaming pass writes a _candidate_ `defineJob` to `jobs/pending/` and sends one message: "I'll just do this every week now." A human approves before it lands. The agent earns autonomy by demonstrating it first — the Phase-2 differentiator made concrete. _(Already-noted crystallize-patterns mechanic + dreaming pass + a human-in-the-loop approval step.)_
- **Mini Comic Strip** — WHO × `comic` → a 3-panel strip (~60mm wide) starring the kid and their current obsession, block-art borders. Receipt proportions _are_ comic-strip proportions. _(Haiku + new ESC-POS panel layout.)_
- **Pickup Coordinator** — auto-resolve "who's getting which kid, from where, when" from the calendar into one line per kid. Kills the daily "wait, who's getting Kid2?" text. The heuristic (which events are pickups) is the hard part. _(calendar + config kids/activities + a pickup classifier.)_

## Useful prints (added 2026-06-25 — utility over delight)

The Top 10 leans fun; these are the boring-but-genuinely-useful prints the family will reach for. All reuse the existing pipeline.

### U1. Week-Ahead Family Calendar

**Pitch:** WHO=`family` × `week` (or a Sunday-evening cron) → the whole household's next 7 days on one sheet, grouped under day headers (MON / TUE / …) with people chips, a printed planner you stick on the fridge.
**Why it fits:** Pure logistics — the highest-frequency "what's on this week?" question, on paper. `getCalendar({ range: 'week' })` already exists, and the **day-grouped renderer we just built for the weekend lookahead** (`weekendEventRows` day-prefixing in `sections.ts`) generalizes straight to a 7-day view.
**Effort:** S · **Leans on:** existing `calendar` tool + generalize the weekend day-grouping to range `week` (new `week` composer, no new tool).
**First step:** add a `week` composer that runs the weekend renderer over `range: 'week'`, grouped by day; wire a `/print/week` + admin button + (later) a WHAT-dial position.

### U2. Movie Night Pick (your idea — the button that suggests what to watch)

**Pitch:** A `movie` WHAT-dial position / button → the agent suggests the next family movie and prints a ticket: title, year, runtime, age rating, a one-line "why this one tonight," and where to watch.
**Why it fits:** A real recurring decision ("what do we watch?") made delightful and on-paper, kid-safe by construction (agent constrained to family-appropriate + your prefs — no free-text). The `tmdb` tool already exists for metadata/ratings.
**Data — the part you'll design:** the pick is only as good as the family's taste store. Cheapest path that already half-exists: a **TickTick "movies"/"watched" list** (the planned `enrich-lists` job already TMDB-enriches movies/tv — so watch history + a ⭐ or tag for liked/disliked could live there), or a small `movie_prefs` config block (genres the kids love, ratings ceiling, "no scary"), or a tiny DB table later. The agent reads {watched + prefs} + `tmdb` → one pick (+ 1 alt).
**Effort:** M · **Leans on:** `tmdb` tool (exists) + a family movie store (your call: TickTick list / config / table) + a `movie` composer + a bounded agent call (Haiku).
**First step:** decide the store (lean: TickTick "movies" list, since `enrich-lists` already touches it); add a `pickMovie` agent call that takes recent-watched + prefs + tmdb candidates → one recommendation; render the ticket.

### U3. Week-Ahead School Planner (per-kid)

**Pitch:** Sunday print, one sheet per kid: the week's notable school shape — sport days + gear, library day, any Sentral-flagged events (excursions, assessments), canteen days. "Mon: library (return books). Wed: sport (boots). Fri: excursion — permission slip due Thu."
**Why it fits:** Front-loads the week's school logistics that currently surface as morning scrambles. Reuses `sentral` + `calendar` + the `activities→gear` map; it's the weekly companion to the daily SCHOOL section.
**Effort:** M · **Leans on:** `sentral` (timetable/events) + `calendar` + activities config (new `school-week` composer, existing tools).
**First step:** aggregate the kid's next-5-school-days from the Sentral cache + calendar into a per-day line; render Sunday alongside the family week sheet.

### U4. Weekly Meal Plan (the week view of the Meal-Plan Strip, #7)

**Pitch:** Sunday → the week's dinners on one sheet from the meal-plan TickTick list, with the week's defrost/prep actions called out ("Wed: defrost chicken Tue night"). The planning artifact, not just today's two lines.
**Why it fits:** Same data as #7, weekly horizon — the actual "plan the week's meals" surface families want on the fridge. Zero new tools.
**Effort:** S · **Leans on:** `ticktick` meal-plan list (same as #7) + a 7-row renderer.
**First step:** once #7's `mealplan` list convention exists, add a `mealweek` composer rendering all 7 days + extracted prep actions.

## Skip / not chota (so they're not re-proposed)

- **Photo-of-the-day on the thermal printer** — 1-bit dithered photos look muddy on receipt paper and the emotional payoff is small at that fidelity. _Where it belongs:_ the deferred e-ink path (`/eink/[who].png`), which is built for dithered images — not the thermal slot.
- **News headlines / quote-of-the-day / word-of-the-day** — the canonical week-3 deaths (confirmed across every surveyed printer project). Don't give them a WHAT-dial slot. A _kid-rewritten_ science/animal line can ride the existing rotating-sections logic at most, never a standing section.
- **A "note to box" write-back slot (camera/OCR)** — tempting, but it's a free-text input surface, which breaks the kid-safe-by-construction guarantee and is a Phase-3 hardware project. _Keep only the carpentry:_ cut the pencil-groove + slot geometry now so a scanner _could_ drop in later — zero code today.
- **Pencil-groove "Note to Box" as a live feature** — same reason; charm + affordance now, no scanner.
- **Times-Table Streak / flashcard learning** — risks week-3 death unless a parent actively reinforces it; learning that _requires_ an adult to nag isn't sticky. Only revisit if a Star Chart-style _physical_ streak object carries it.
- **Generic chat surface / dashboard widgets / kiosk-mode polish** — explicitly not-next per `next.md`. The box's screens are ambient (clock + dial feedback), not dashboards; the agent's home is Telegram + the printed line, not a chat wall.
- **Mood Palette / per-brief SVG header that shifts on mood** — lovely in theory, but inferring "exam week" or "hard day" reliably is fragile and the signal is invisible unless explained (which defeats it). Park until memory is mature and trustworthy.
- **Library due-date / canteen-balance scrapers** — genuinely useful but gated on per-council / per-school API availability that varies wildly; high-friction, low-certainty. Keep on the `tools.md` wishlist, not the shortlist.
