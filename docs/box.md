# The chota box

The Pi 5 counter-top box: thermal printer, a control deck of dials and a big PRINT button, a lid screen, speakers, a mic array and a camera. One power cord. This is the hardware plan; [`next.md`](next.md) has the overall direction, [`pi5-readiness.md`](pi5-readiness.md) the RAM/CPU budget and verified screen picks.

## Status (2026-10-15)

- **Running today:** the X230 (`pop-os`), headless, Node 24. The Pi 5 + Active Cooler + PSU + Pico 2 WH + panel parts are on hand (June 2026 order, received); no screens yet. Next: Phase 1 below.
- **Still to buy:** microSD (A2, 32–64GB), LED resistors, the lid screen (Waveshare 8" DSI LCD (C), 194 × 119, v11) and a 300–500 mm 22-pin DSI cable for the Pi 5, ReSpeaker Lite (bare USB board), one SB Acoustics SB65WBAC25-4 (Wagner) + a TPA3116 amp + a 24 V 5 A brick with a DC Y-splitter + USB sound card, a TALK button, Pi Camera Module 3 + Pi 5 camera cable, the face (GlowBit 8×8 + level shifter + 24→5 V buck), an LD2450 radar, an SK6812 strip, three small buttons, an analog panel meter, JST-XH connectors, a soldering iron.
- **Open calls:** see §Open questions at the end.

## Phase 1 — the Pi as the always-on home server (no screens yet)

Decided 2026-10-15. The Pi takes over from `pop-os`; the X230 is then wiped for Omarchy testing. Screens and the box come later.

- **OS: Raspberry Pi OS Lite 64-bit (Trixie).** The only option with first-party DSI panel support, and labwc (the planned kiosk compositor) is its default. Ubuntu delivers arm64 Chromium as a snap and leaves the panel setup to you; DietPi had Pi 5 + kiosk friction on Trixie. Security-only `unattended-upgrades`, zram, journald `Storage=volatile` (or log2ram) to spare the SD card.
- **Storage:** boot from SD now; add a USB SSD for `data/` and the family home folder once photos and PDFs arrive.
- **Ethernet, not Wi-Fi**, for an always-on server and subnet router; Wi-Fi from the Imager pre-config is only the fallback.
- **Hostname `chota`.** Parallel-run against `pop-os`, move the printer cable, watch one 06:45 print, then retire the laptop.
- **Alongside chota:**
  - **Tailscale** with subnet routing, to reach the home network from anywhere.
  - **Nightly backup** of `data/home.db` (`sqlite3 .backup`), a `git bundle` of the home-folder repo, and its `files/`: rsync to the Mac, or `rclone crypt` to Drive. Litestream only if a day's loss ever matters.
  - **`ko` (kotools)** via `uv tool install`, signed in as the bot's own Google account (OAuth app set to "In production", so no 7-day token expiry; see [`memory.md`](memory.md) §Shared Google Docs and Sheets). Setup: on the Mac `ko google auth chota`, copy `~/.local/state/ko/google_token_chota.json` to the Pi (self-contained), then `ko google use chota` there; KO shares the Drive folder (Editor) and the family calendar ("Make changes to events") with the bot account. Not a service account: it has no storage quota, so it can't create files in a personal Drive. Google Keep isn't workable. The agent calls specific `ko` commands as typed tools (`ko hn`, `ko tv`, `ko fetch`), never a general shell. Not yet tried on arm64.
  - **An uptime ping** (Healthchecks.io, free) from a cron job, so a dead box gets noticed.
  - **The family home folder** — see [`memory.md`](memory.md).
- **Skipped for now:** Pi-hole (if it dies the house loses DNS), Home Assistant (~0.5GB, nothing to automate yet), Syncthing (git covers sync).
- **Railway — optional, later.** chota stays on the Pi (the printer is USB). An always-online outside piece earns its keep only for: public share links to artifacts (grandparents without Tailscale), an off-site backup bucket, or a dead-man's switch that alerts when the Pi goes quiet. Healthchecks.io and the Mac's copies cover the last two for free today.

## What changed since the June plan

- **Chromium on arm64:** Chrome for Testing (what `agent-browser install` fetches) ships no linux-arm64 build. Use the OS `chromium` package via `AGENT_BROWSER_EXECUTABLE_PATH`. Lightpanda was considered and ruled out: it has no graphical renderer, so it can't make the print screenshots.
- **Runtime:** stay on Node. chota runs unchanged under Bun (tested 2026-10-15: same page speed, ~60MB less RSS), so it's an option later, most naturally with SvelteKit 3's `adapter-bun`. Match the Pi's Node major to the X230's (24) at migration, or bump both together.
- **Sleep/wake safety:** the scheduler now skips any cron fire more than 10 minutes late, so a box that's been off or asleep never prints a stale brief on boot.
- **Drawings:** [`box-design/`](box-design/) builds the "Chota Box Designs" page (https://claude.ai/artifact/GhhArcB5XuyjeBEBTQW8dC): the box with working lids, dimensions and a cut list, and a wall-plate alternative. v8 (18 Oct): 424 × 262 × 184 mm; the lid is just the screen (20 mm), two 3.5" speakers share one sealed ~1.9 L chamber behind the front wall, no mains inside, and the printer (kept: the MUNBYN, about 140 × 180 × 125) still needs measuring. Where it differs from this doc, the page is newer. Every size hangs off the printer, which still needs measuring.
- **Two earlier drafts are archived:** [`archive/dock.md`](archive/dock.md) (official Touch Display 2 screens — later rejected for their bezels) and [`archive/dial.md`](archive/dial.md) (a wall-mounted dial + e-ink; became the box's deck). The dial draft's software design is folded into §Panel software below.

## Pi 5 migration

Ordered 11 Jun 2026 (Core Electronics order #1000690836, express post): **Raspberry Pi 5 4GB** + official 27W PSU + Active Cooler, plus the control-panel parts below. **Still to buy separately:** a microSD card (A2-rated, 32–64GB — the Pi won't boot without it) and a 220–470Ω resistor assortment for the 10mm LEDs.

- **OS:** Raspberry Pi OS **Lite** 64-bit (headless, Debian-based — `chota.service`, Caddy, and the deploy ritual transfer unchanged). Flash with Raspberry Pi Imager with Wi-Fi + SSH key + hostname baked in; no monitor ever attached.
- **Migration:** same as any box swap — `npm install` rebuilds native modules (better-sqlite3, node-usb) for arm64, copy `data/`, install the service, plug in the MUNBYN. Per `CLAUDE.md`, only `/etc/hostname` cares which box.
- **Why Pi over the X230:** ~3W idle vs ~10–15W, silent, small enough to mount on the eventual panel, GPIO for buttons/dials/e-ink HATs. Trade-off accepted: no built-in battery/UPS.
- **No case.** The Pi mounts exposed on brass standoffs — bare on a shelf first, then inside the box (see below). The Active Cooler matters (the daily agent-browser Chromium screenshot is a real CPU burst).
- **No portable LCD.** Considered a ~$100 USB-C/HDMI portable monitor for the board; rejected — it recreates the backlit dashboard the family already ignores, adds two cables, and the $100 is better banked toward the e-ink panel. The Pico's tiny screen covers selection feedback; everything else is paper.

### First boot (when the order arrives)

The Pi deltas only — from step 4 on, [`deploy.md`](deploy.md) §First-time bootstrap (or `deploy/bootstrap.sh`) is already written for a fresh box and applies as-is.

1. **Flash the SD** with Raspberry Pi Imager on the Mac: Pi 5 → Raspberry Pi OS **Lite (64-bit)** → ⚙️ pre-config: hostname **`chota`** (finally matching plan.md's original `chota.local`; portless URL becomes `http://chota/`), user `ko`, home Wi-Fi creds, paste the Mac's SSH public key, locale/timezone `Australia/Sydney`. No monitor or keyboard ever needed.
2. **Clip on the Active Cooler before first boot** (push-pins into the two board holes, fan cable to the 4-pin header next to the USB-C port).
3. Boot, wait ~90s, `ssh ko@chota.local`.
4. **Box baseline:** `sudo apt update && sudo apt full-upgrade`; install Tailscale (curl script) and `fnm` + **Node 26** (`chota.service` points at the fnm default-alias node path). Node 26 is current, not LTS, until late October 2026 — the Mac already runs 26.11 with chota's tests green, and the Pi build lands about when it turns LTS. Bump `@types/node` to `^26` in the same change (it tracks the box). Runtime decision (2026-10-16): Node, not Bun — see [`handover.md`](handover.md). Globals: `npm i -g agent-browser @anthropic-ai/sandbox-runtime` (srt also needs `apt install bubblewrap socat`). Update the `chota` SSH alias in the Mac's `~/.ssh/config` to the new host.
5. **Run the existing bootstrap** — deploy.md Phase 1 / `bootstrap.sh`: apt prereqs + plugdev + cups-off, clone `chota-bot` _and the sibling `curios`_ into `~/code/`, scp `.env` + `chota.config.ts`, append `PORT`/`KIOSK`, udev rule, build, `chota.service`, Caddy. **`agent-browser install` won't work on arm64** (Chrome for Testing has no linux-arm64 build): `sudo apt install chromium` and set `AGENT_BROWSER_EXECUTABLE_PATH` in `chota.service`. Run the screenshot path once by hand before trusting the 06:45.
6. **Parallel-run, then cut over.** Keep the X230 in service; bring the Pi up fully, move the MUNBYN's USB cable last, watch one real 06:45 from the Pi, then retire the X230. (The printer cable is the natural mutex — only the box it's plugged into can print.)

## The box ("steampunk appliance")

Concept settled June 2026 (evolved from an earlier wall-board idea): an **all-in-one counter-top box** — wooden, portable, everything inside, one power cord. Cash register × toaster. Sits on a kitchen counter; collapsible for transport; potentially buildable as a gift unit for other families (the `chota.config.example.ts` pattern already makes the software per-family swappable; for Wi-Fi onboarding without keyboard or touch, a **captive setup portal** — comitup/RaspAP-style `chota-setup` hotspot + phone browser — beats any dial-entry scheme).

```
   OPEN (interactive)                               CLOSED (ambient)
            ______________________
           / [Inky 7.3" Spectra 6]/ ← main lid,        ┌──────────────┬───────┐
          /   on inner face      /    open ~75°        │  plain box   │▒slot▒ │ ← still
         /______________________/                      └──────────────┴───────┘   prints!
        ┌═══ recessed deck ═════╦═══════════╗
        │ WHO ◉ [5" panel] ◉ WHAT║ ▒ paper ▒ ║ ← slot in the FIXED top panel
        │ ⊓⊓⊓ toggles   screen   ║ ▒ slot  ▒ ║
        │ (meter)  ●●  ((PRINT))║───────────║ ← service lid (flips up:
        │ ✎ groove   ░ mic/PTT ░║ printer   ║    roll changes)
        ├───────────────────────╩───bay─────┤
        │ ░ spkr ░                 ░ spkr ░ │ ← front face: 2 drivers
        └─────────── one power cord ────────┘    behind brass grilles
          left ~300mm: deck + screen lid · right ~185mm: printer bay
          inside: Pi 5, amp, sound card · Pico under deck · bricks outside
```

**Box engineering decisions:**

- **Two modes; the main lid is the mode switch.** Controls live on a deck _under_ the main lid; the paper slot is in the fixed top panel over the printer bay. Closed = plain ambient box that still prints the 06:45 unattended (and toddler-proofs the toggles). Open = screen up + control deck revealed. Wire a **lid-detect switch** (reed/microswitch → Pico) so opening wakes the tiny screen / LEDs and closing returns to ambient.
- **Two lids, battleship style.** Main lid (left, ~300mm wide × **200–220mm deep — not the full box depth**; a fixed top strip behind the hinge line keeps open height to ~400–415mm total under kitchen cabinets, and gives the hinge + vent somewhere solid) carries only the lid display on its inner face (the 10.1" panel module ≈ 235×161mm fills a 300×220 lid like a framed picture; 10.1" is the size ceiling before the box must grow). Closed = glass protected facing down; open = counter viewing angle. Service lid (right, thin flap) flips up over the printer bay for roll changes (~monthly). The **slot is cut into the service lid** (changed in the drawings: the printer's cover hinges at its back, so a fixed panel over the exit would block it); two dowels seat the lid so the slot always lines up.
- **Lid settles at one angle: ~70° from horizontal** (Nest-Hub-style ~20° lean-back, right for counter height viewed standing). Mechanism: exposed brass butt hinges + a **brass chain or leather strap** that goes taut at 70° — one position, zero mechanism, period-correct. Upgrade option if two positions prove wanted: a notched **quadrant stay** (~55° looking-down + ~75° across-the-room).
- **Deck sits at ≈ printer-top height** (~160mm), recessed 35–40mm below the ~205mm rim — one box height outside, sunken control deck inside. The cavity _under_ the deck is ~109 mm tall in the v8 drawing. Its front 90 mm holds the speaker chamber, so **everything deep on the deck (arcade button ~40 mm, pots and meter ~30–40 mm, toggles) sits in the back 118 mm**, above the Pi (≈45 mm on standoffs); the deck over the chamber stays clear (tear-off zone, nameplate). Layout: Pi on the floor (ports facing the back wall, right-angle plugs), amp by the divider where the 24 V lead comes in, sound card on the floor at the left, Pico on the deck's underside at the back-left clear of the meter and dial pots, speakers low at the front. **Service access: the deck panel screws down with exposed brass screws and lifts out as one wired harness** — unscrewing it is how the box opens for surgery (alternative: removable base). If the exposed-Pi look is still wanted, it's a mesh/glass window in the equipment-bay side wall, not deck space.
- **Deck is recessed below the box rim** by 30–40mm so the lid closes flat over wooden knobs and toggle bats (easier to build than a tray-lid, and the rim shields the controls). Spare deck space earmarked: an **analog needle meter** (PWM ≥1kHz from the Pico through a ~3.3 kΩ series resistor (for a 0–1 mA meter at 3.3 V) + smoothing cap — minutes-to-bus or today's max temp), a **pencil groove + tear-off zone**, a **mic + push-to-talk spot reserved for Phase 3 voice** (drill now, fill later — the speakers live on the front face, see below), brass CHOTA nameplate. **Wood-thickness gotcha (find out before cutting the nice wood):** pot/toggle bushings carry only 6–8mm of thread — counterbore each mount from the rear with a Forstner bit down to a 4–5mm skin, or inset a 1–2mm aluminium sub-panel. Wire the harness in **JST-XH, not Dupont** (Dupont loosens in a box that gets moved).
- **Paper exits the top; printer sits flat on the box floor** — dead-straight path, toast-pop theater, and the top is where roll-change access lives anyway. (The MUNBYN _does_ advertise wall-mount support, so a front-exit vertical mount à la paper-console is viable — considered, not chosen.) **Auto-cutter caveat:** a cut sheet stands loose in the slot, and the 06:45 prints several briefs in sequence — either add a small catch tray beside the slot or skip auto-cut for the morning batch. Test with the real printer before cutting wood. **Slot detail (field research):** thermal paper curls toward its printed face — fit a 10–15° outward-angled guide at the slot so the leading edge can't fold back in and jam the next print; slot width ≥4mm. **Paper:** switch to phenol-free 80mm rolls (Blue4est or ascorbic-acid developer, ~20% premium) before kids handle paper daily, and buy rolls with an end-of-roll indicator stripe. Vent the printer bay too — heat slowly pre-activates thermal coating (grey backgrounds).
- **Pi = server + both screens; Pico = the entire control surface.** With the lid going LCD (below), the Pi's 40-pin GPIO header is **completely free again** — no HAT, no through-hinge SPI jumpers. The through-hinge cable is now the lid panel's **DSI FFC**, and the strain-relief rules still apply: route along the hinge axis with 6–8cm of slack so it bends on a large radius on every open/close, never at the connector; FFCs have finite flex cycles, so leave a generous service loop. All dials/toggles/button/LEDs go to the Pico, which connects to the Pi by one USB cable (data + power) — udev rule pins it to a stable `/dev/ttypico`, JSON-lines protocol (debuggable with `cat`), and a two-sided watchdog (Pico self-resets if the host goes quiet; host re-opens when the tty reappears) so reboots/deploys never wedge it.
- **Lid display — re-decided June 2026: Waveshare 10.1" DSI LCD (C)** (Core Electronics $129.95, 1280×800 IPS landscape-native, bare-PCB look; + 22→15-pin FPC adapter ~$5–10). The **literary clock** flipped this from e-ink: per-minute content is physically impossible on Spectra 6, `/clock` already exists, and the panel is bigger _and_ cheaper than the Inky. **Verified sysfs backlight 0–255** (`dtoverlay=vc4-kms-dsi-waveshare-panel,10_1_inch`; `echo N > /sys/class/backlight/*/brightness`) → an evening-dim + night-off schedule job is the contract that keeps this from becoming the ignored glowing dashboard again. Theme it warm/dark sepia. **HDMI panels are disqualified for the lid:** `ddcutil setvcp` (DDC/CI brightness write) is broken on Pi 5 Bookworm (open bug, ddcutil #356) and budget panels — including the considered GeeekPi 7" — have OSD buttons only. Fallback pick: official Touch Display 2 7" ($106, first-party sysfs, smaller + chunkier bezel). Mounting rules unchanged: routed rebate, panel held by its edges, anti-glare surface or film.
- **One screen — decided 17 Oct 2026** (superseding the dual-screen plan below): only the 10.1" lid panel, on DSI. The deck is reachable only with the lid open, and then the lid screen faces you, so dial selections show there. This frees the second CAM/DISP port for a **Pi Camera Module 3** (front rim, brass slide shutter, on-LED), means one Chromium kiosk instead of two (per-output placement under labwc was the flaky part), and drops ~A$80. The deck gets an analog needle meter where the 5" screen was. The 5" notes below stay for reference. **Gotchas (Gemini review, 17 Oct):** the Waveshare panel takes its own 5 V (4-pin header, ~0.9 A), so a power lead runs through the hinge beside the ribbon; with the Pi on the box floor the DSI ribbon is long (~400 mm, use the 500 mm cable) — test a long run before committing. Measure the panel outline before routing the rebate.
- **E-ink: deferred, not dead.** The Inky Spectra 6 ($150.40 at Pi Australia, currently backordered) lost to the LCD on price, size, and the clock. Its niche — zero-glow paper look, battery-powered Pico satellites elsewhere in the house — can return later; the hard-won Spectra 6 knowledge (20–25s real refresh, no partial refresh, palette-snap-text/Atkinson-photo dithering, FPC handling) is preserved in [`inspiration.md`](inspiration.md) §Field notes.
- **Mic and TALK (decided 17 Oct 2026):** the **ReSpeaker Lite**, bare USB board (2-mic XMOS XU316, hardware echo cancelling, about A$43 at Core Electronics; not the A$85 kit), flat behind the front rim above the deck, away from the speakers. **TALK** on the front wall, wired to the Pico: hold it and the box pauses its own sound and listens. Echo cancelling only really matters for a wake word heard over music; the Lite tops out at 16 kHz, so music played through it would sound thin, and music played around it gives it no echo reference. If wake-word-over-music becomes a goal, the XVF3800 (4 mics, A$113, a 48 kHz USB firmware) can carry the music and cancel it. A DIY bare-mic array was ruled out: more than stereo on the Pi 5 needs custom device-tree work, and software echo cancelling struggles with speakers 10 cm away.
- **Screens (decided 18 Oct 2026, v9):** the 10.1" DSI in the lid stays the main screen. Three small amber OLEDs (2 × 1.3" behind the dials, 1 × 2.42" by PRINT, Waveshare, ~A$24) under smoked acrylic, driven by the Pico, show dial values and chota's status. A Waveshare 4.2" e-ink module (400 × 300, black/white/red, 103 × 78.5 board, Core Electronics A$57.60; picked over the A$151 Inky 4") in the printer lid behind the slot shows the day with the box shut, on an 8-wire SPI cable to the Pi 5's pins (check Waveshare's code on Pi 5 GPIO). No second DSI screen: the camera keeps the Pi 5's other port; a small touchscreen later would be HDMI. The 7.3" (174 × 123) doesn't fit that lid without growing the box; it suits a separate 13 × 18 cm frame with its own Pi Zero 2 W if wanted later.
- **Driving the small screens (researched 18 Oct 2026, unverified on hardware):**
  - **E-ink and face, from the Pi:** one long-running Python helper (`hw.py`) that chota starts and writes JSON lines to: push a PNG to the e-ink, set the face's state. It animates the face itself, so a state change shows at once. No Node package suits the Pi 5. Waveshare's current `epdconfig.py` uses gpiozero (lgpio on the Pi 5) and spidev. Needs `python3-gpiozero python3-lgpio python3-spidev` and SPI enabled.
  - **Pins:** e-ink on SPI0 CE0, RST 17, DC 25, BUSY 24; face data on GPIO 13. Nothing else in the box uses them.
  - **Rendering:** chota renders a 400×300 `/eink` page and screenshots it with agent-browser, as prints already work. Map each pixel to black, white or red, with no dithering, into the driver's two planes.
  - **Cable:** Waveshare says 20 cm at most and ours is 30–40 cm. Drop SPI to about 1 MHz (a frame is still ~0.25 s) and run ground beside the clock line.
  - **Module version:** `epd4in2b_V2.py` reads a chip ID over MISO, which the 8-wire cable lacks. If it picks the wrong version, hard-code it.
  - **OLEDs, from the Pico:** MicroPython. The two 1.3" go one on each I2C bus, so both keep address 0x3C. The 2.42" goes on SPI.
  - **Dimming the OLEDs:** dim with `0x81` and a level. On the 2.42" SSD1309 the lowest level barely dims it, so "dark" means display off (`0xAE`). Shift the layout 1–2 px every few minutes against burn-in.
  - **Pi ↔ Pico:** newline-delimited JSON over USB serial, using `serialport` on the Pi.
  - **Bench order:** Waveshare's `epd_4in2b_V2_test.py` on a short cable, then at 40 cm, then the `/eink` page through the colour mapping, then one OLED and the serial loop.
- **Smaller box (decided 18 Oct 2026, v11): 361 × 254 × 165 mm, from 424 × 262 × 184.** Feedback was that 40 cm is too wide. The width is the lid plus the printer, so: **8" Waveshare DSI LCD (C)** (194 × 119 per Waveshare's drawing, 1280×800, same sysfs dimming; US$79) instead of the 10.1"; **no divider**: a hardwood post and rail carry the deck's right edge, the speaker chamber's 12 mm end panel is the front post, the lids rest on the front wall and hinge strip, and four blocks on the base locate the printer 3 mm clear. **One SB Acoustics SB65WBAC25-4** (2.5", 4 Ω, Wagner Electronics) replaces the ND91 pair: mono, ~0.9 L sealed (Qtc ~0.83), clear mids and wide treble (audioXpress bench), bass EQ usable to ~90–100 Hz at full kitchen volume. Stereo from drivers 15 cm apart adds little; a tweeter adds little over the SB65 (the amp's spare channel can take one later, crossover in DSP). Its 64 mm frame drops the box to the printer's height plus the lid, and the face sits beside it inside the sealed chamber (acrylic glued over its window; wires out through one sealed hole). The radar, knob and buttons stay on the bay front with 15 mm clear in front of the printer. Printer measured 140 × 175 (about) × 130. Still to check: the printer's exact depth (sets D), the SB65's cut-out (drawn 56 mm, assumed), and the 8"'s 8 mm standoffs (leave them off; ~9 mm behind the glass in the lid). Checked and dropped: 7" Touch Display 2 (only ~5 mm narrower, 720×1280 portrait), Dayton DMA58 2" (too little cone travel), SB36 1" (a tweeter in practice), ND65 (no AU stock).
- **The face (decided 18 Oct 2026, v10):** the speakers fill the left front (12.5 mm between their frames), so the face goes on the printer bay's blank front. **GlowBit Matrix 8×8** (Core CE08033, WS2812B, 61 mm square, A$16.60, in stock) behind smoked acrylic: wake, listening, thinking, talking, roll call; RGB, so amber by default and a colour per state if wanted. **The Pi drives it** (the wake word and agent run there) via Adafruit's Pi 5 PIO NeoPixel library (`Adafruit-Blinka-Raspberry-Pi5-Neopixel`, needs `/dev/pio0`; young, rc releases only), through a 74AHCT125 level shifter, powered by a 24→5 V buck on the 24 V lead rather than the Pi's supply; cap brightness in software. Fallback if the library misbehaves: move its data wire to the Pico and send the state over serial. Checked and dropped (Sonnet survey): the 15×7 and 16×9 IS31FL3731 boards (wide, not square), HT16K33 8×8 tiles (no per-pixel dimming, out of stock), the IS31FL3741 13×9 (fine I2C fallback, 51 × 39), HUB75 panels (Pi 5 library alpha, amps of current, too deep), Unicorn HAT Mini (likely clashes with the e-ink's SPI0). Two GlowBits tile to 16×8 if 8×8 reads too coarse. **Around it:** an HLK-LD2450 radar (angle + distance, up to 3 people; replaces the LD2410 idea) behind a plain window under the face, on the Pico's UART; an SK6812 5 mm strip in a groove along the base's front edge, run by the Pico, whose LEDs facing whoever walks up glow dimly; a knob (the EC11, volume) and three small buttons below, to the Pico. Their wires cross the divider through a Ø10 hole behind the speaker chamber. Bay vents: two thin slots at the front, the rest across the back plus a styled vent on the right end. **Depth:** with the printer listed 180 deep only 18 mm sits behind the bay front: flat boards and a counterbored encoder fit, a panel pot doesn't. Measure the printer.
- **Materials, buying and tools (researched 18 Oct 2026, Sonnet; Sydney prices mostly unverified):** thinner ply buys little: keep 12 mm birch ply for the base (light-strip groove), front (speaker rebates, encoder counterbore), back (grommets, cleat) and divider (lid edges, chamber wall); only the two ends can drop to 9 mm (saves 6 mm of width; glue + pins, since screws hold poorly in 9 mm edges). Deck 9 mm, skins and chamber panels 6 mm, lid frames and hinge strip Tas oak (hinge screws, the 7.5 mm screen rebate). For a lighter look, chamfer or round the lid and top edges 1.5 mm. Birch ply with its layered edges left showing under hardwax oil (Osmo/Rubio) suits the oak and brass; hoop pine ply if painting. Finish before fitting hardware and acrylic. **Buy:** Tas oak at Anagote Timber, Marrickville (cuts and dresses to size); birch ply from a sheet merchant who panel-cuts (phone first); Bunnings ply is fine only for a mock-up. Skip CNC for a first build (no confirmed Sydney DXF service; Plyco in Vic takes DXFs). **Tools:** own a drill/driver, 4–6 bar clamps plus 2 small, square, rule, marking knife, chisel; borrow a trim router (rabbet + straight bits, circle jig), an 85 mm hole saw and a sander from the Sydney Library of Things (North Sydney) or a workshop such as Makerspace &Company (Marrickville). Touch present on all — leave unconfigured.
- **Off/wake mechanics (research finding — don't trust DPMS):** `wlr-randr --off` / compositor DPMS blanks the image but **leaves DSI backlights glowing** (long-standing Pi firmware gap). The reliable off is a sysfs write: `echo 0 > /sys/class/backlight/*/brightness` (plus `bl_power` where present), granted via a narrow sudoers entry and called by the panel listener — wake on any Pico event, sleep on a 3–5min idle timer. If the Waveshare's minimum brightness leaves a faint glow, the documented fix is swapping the BL resistor 100K→68K (a one-joint solder job, perfectly on-theme). For later wake-on-approach: **LD2410 mmWave on the Pico's UART, not PIR** (PIR goes blind on a person standing still); needs per-gate threshold tuning in engineering mode first — kitchen fans and fridge compressors false-positive on defaults.
- **Kiosk stack is an apt-install, not a reflash:** keep OS Lite; when the screen lands: console-autologin → **labwc** (research verdict: Pi OS's own compositor with the documented kiosk path; `cage` fights XDG_RUNTIME_DIR/root when systemd-launched) → Chromium as a user service with `Restart=always` and `--kiosk --ozone-platform=wayland --noerrdialogs --no-first-run --disable-session-crashed-bubble --disk-cache-dir=/dev/null`. Add a **nightly restart timer** (long-running kiosk Chromium leaks RAM over 2–3 days). The `/panel` page reloads itself on an SSE `deploy` event the server emits at boot — fresh UI after every `npm run deploy`. (`--kiosk` blocks DPMS, which doesn't matter — our off-switch is the backlight sysfs write.)
- **Touch stays off.** The screen displays; the brass controls control — touch would cannibalize the dials.

## Devices all speak HTTP — the one architecture rule

Every physical device is a dumb client of the chota server. No device-specific logic in the server beyond a route.

- **Controls → server:** the panel controls fire `POST /api/print/[kind]` — the route that already exists and already drives every print. Whether the dials hang off the Pi's own GPIO (a small script POSTing to `localhost:8000`) or off the Pico (POSTing over Wi-Fi, or USB-serial into the Pi) is an implementation detail the server never sees.
- **Pico owns analog.** The Pi 5 has **no ADC** — the pots can only be read by the Pico (3 ADC pins). Toggles/buttons/encoder are digital and work on either. The Pico also drives the tiny selection screen. A Pico over USB is also a fine "GPIO co-processor" (power + rock-solid serial in one cable, Wi-Fi unused).
- **Displays ← server:** both box screens are just Chromium kiosk windows on chota routes — the lid shows `/clock`, the deck shows `/panel`. And the print pipeline already renders any person's brief as a server-side PNG at a fixed pixel width (the agent-browser screenshot of `/print/[who]`), so a _deferred_ e-ink client — battery-powered Pico 2 W + small panel that wakes, fetches a pre-dithered PNG from an `/eink/[who].png` route, displays, deep-sleeps — stays dumb too. **The hard part is already built.**

## What this leans on (already shipped)

- `POST /api/print/[kind]` — print any format on demand; the panel button is just a new caller.
- `/print/[who]` rendered bare + screenshot → PNG → `printPng()` — the server-side-image pipeline e-ink reuses.
- `defineJob()` cron system, `/admin/jobs`, `/api/health` — the ops surface a headless box needs.
- Deploy + `chota.service` are box-agnostic by design.

## Panel software (from the dial draft, still the plan)

- **Firmware is dumb; chota owns all logic.** The Pico reports raw input (dial positions, encoder steps, button/toggle edges) as JSON lines over USB serial and knows nothing about kids or print kinds. Menus, labels and the WHO/WHAT mapping live in TypeScript, so a new print format shows up on the deck with no firmware change.
- **In-process, gated.** A `bootPanel()` from `hooks.server.ts` next to `bootJobs()`, only when `KIOSK=true`; it opens the port with `serialport`, finds the Pico by USB VID/PID (`2E8A`), and re-opens with backoff when the device disappears (replug, reboot, brownout). Calls `composeImage()` + `printPng()` directly, so it shares the printer mutex; prints log as `event('panel', …)`.
- **Build it before the hardware.** Pure, unit-tested pieces (protocol parse, menu from `getPrintKinds()`, a state machine idle → printing → done/error/busy) plus a web simulator at `/admin/panel` with on-screen dials and buttons driving the same controller. The real Pico is then a transport swap.
- **Host owns state.** The Pico sends deltas and edges, never absolute menu positions, so a dropped event can't desync the menu.
