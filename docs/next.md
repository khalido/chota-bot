# What next

Direction + near-term plan, as of June 2026. This supersedes the scattered idea lists for "what do we actually do next" — the archives are still worth mining: [`plan.md`](plan.md) §Phase roadmap + §v3 candidates, [`tools.md`](tools.md) §Future ideas, [`audit-2026-05.md`](audit-2026-05.md) §Future Plans + §Useful Feature Ideas, [`inspiration.md`](inspiration.md).

## The direction shift (June 2026)

Phase 1 shipped and the lesson is in: **the print is the product, the dashboard isn't.** The family reads the morning receipt; nobody looks at the screen on the wall. So:

- **Print-first.** New features should make the printed brief better or add new print formats — not new dashboard screens.
- **Headless server.** The kiosk box becomes a server you SSH into, with the web UI reached from phones/laptops on the LAN when needed. Kiosk mode (Chromium fullscreen, night-dimming, auto-cycle — plan.md Phase 2) is **deprioritized**, not deleted.
- **Ambient surface = the box lid's dimmable display.** _(Revised June 2026 — originally "e-ink, later".)_ The lid carries a 10.1" DSI panel running the literary clock, dimmed on a schedule and off at night — the no-glow-after-hours contract is what separates it from the failed wall dashboard. E-ink is deferred, not dead (see §The box).
- **Physical controls over touchscreens.** The kid interaction we want is: turn a dial, press a chunky button, paper comes out. Not tapping a web UI.

## Hardware plan

### Pi 5 migration

Ordered 11 Jun 2026 (Core Electronics order #1000690836, express post): **Raspberry Pi 5 4GB** + official 27W PSU + Active Cooler, plus the control-panel parts below. **Still to buy separately:** a microSD card (A2-rated, 32–64GB — the Pi won't boot without it) and a 220–470Ω resistor assortment for the 10mm LEDs.

- **OS:** Raspberry Pi OS **Lite** 64-bit (headless, Debian-based — `chota.service`, Caddy, and the deploy ritual transfer unchanged). Flash with Raspberry Pi Imager with Wi-Fi + SSH key + hostname baked in; no monitor ever attached.
- **Migration:** same as any box swap — `npm install` rebuilds native modules (better-sqlite3, node-usb) for arm64, copy `data/`, install the service, plug in the MUNBYN. Per `CLAUDE.md`, only `/etc/hostname` cares which box.
- **Why Pi over the X230:** ~3W idle vs ~10–15W, silent, small enough to mount on the eventual panel, GPIO for buttons/dials/e-ink HATs. Trade-off accepted: no built-in battery/UPS.
- **No case.** The Pi mounts exposed on brass standoffs — bare on a shelf first, then inside the box (see below). The Active Cooler matters (the daily agent-browser Chromium screenshot is a real CPU burst).
- **No portable LCD.** Considered a ~$100 USB-C/HDMI portable monitor for the board; rejected — it recreates the backlit dashboard the family already ignores, adds two cables, and the $100 is better banked toward the e-ink panel. The Pico's tiny screen covers selection feedback; everything else is paper.

#### First boot (when the order arrives)

The Pi deltas only — from step 4 on, [`deploy.md`](deploy.md) §First-time bootstrap (or `deploy/bootstrap.sh`) is already written for a fresh box and applies as-is.

1. **Flash the SD** with Raspberry Pi Imager on the Mac: Pi 5 → Raspberry Pi OS **Lite (64-bit)** → ⚙️ pre-config: hostname **`chota`** (finally matching plan.md's original `chota.local`; portless URL becomes `http://chota/`), user `ko`, home Wi-Fi creds, paste the Mac's SSH public key, locale/timezone `Australia/Sydney`. No monitor or keyboard ever needed.
2. **Clip on the Active Cooler before first boot** (push-pins into the two board holes, fan cable to the 4-pin header next to the USB-C port).
3. Boot, wait ~90s, `ssh ko@chota.local`.
4. **Box baseline:** `sudo apt update && sudo apt full-upgrade`; install Tailscale (curl script) and `fnm` + Node LTS (`chota.service` points at the fnm default-alias node path). Update the `chota` SSH alias in the Mac's `~/.ssh/config` to the new host.
5. **Run the existing bootstrap** — deploy.md Phase 1 / `bootstrap.sh`: apt prereqs + plugdev + cups-off, clone `chota-bot` _and the sibling `curios`_ into `~/code/`, scp `.env` + `chota.config.ts`, append `PORT`/`KIOSK`, udev rule, build, `chota.service`, Caddy. One thing to verify on arm64: `agent-browser install` pulls a linux-arm64 Chromium — run the screenshot path once by hand before trusting the 06:45.
6. **Parallel-run, then cut over.** Keep the X230 in service; bring the Pi up fully, move the MUNBYN's USB cable last, watch one real 06:45 from the Pi, then retire the X230. (The printer cable is the natural mutex — only the box it's plugged into can print.)

### The box ("steampunk appliance")

Concept settled June 2026 (evolved from an earlier wall-board idea): an **all-in-one counter-top box** — wooden, portable, everything inside, one power cord. Cash register × toaster. Sits on a kitchen counter; collapsible for transport; potentially buildable as a gift unit for other families (the `chota.config.example.ts` pattern already makes the software per-family swappable; for Wi-Fi onboarding without keyboard or touch, a **captive setup portal** — comitup/RaspAP-style `chota-setup` hotspot + phone browser — beats any dial-entry scheme).

```
   OPEN (interactive)                               CLOSED (ambient)
            ______________________
           / [Inky 7.3" Spectra 6]/ ← main lid,        ┌──────────────┬───────┐
          /   on inner face      /    open ~75°        │  plain box   │▒slot▒ │ ← still
         /______________________/                      └──────────────┴───────┘   prints!
        ┌═══ recessed deck ═════╦═══════════╗
        │ WHO ◉ [5" panel] ◉ WHAT║ ▒ paper ▒ ║ ← slot in the FIXED top panel
        │ ⊓⊓⊓ toggles   screen   ║ ▒ slot  ▒ ║
        │ (meter)  ●●  ((PRINT))║───────────║ ← service lid (flips up:
        │ ✎ groove   ░ mic/PTT ░║ printer   ║    roll changes)
        ├───────────────────────╩───bay─────┤
        │ ░ spkr ░                 ░ spkr ░ │ ← front face: 2 drivers
        └─────────── one power cord ────────┘    behind brass grilles
          left ~300mm: deck + screen lid · right ~185mm: printer bay
          inside: Pi 5 + PSU bricks on internal powerboard · Pico under deck
```

**Box engineering decisions:**

- **Two modes; the main lid is the mode switch.** Controls live on a deck _under_ the main lid; the paper slot is in the fixed top panel over the printer bay. Closed = plain ambient box that still prints the 06:45 unattended (and toddler-proofs the toggles). Open = screen up + control deck revealed. Wire a **lid-detect switch** (reed/microswitch → Pico) so opening wakes the tiny screen / LEDs and closing returns to ambient.
- **Two lids, battleship style.** Main lid (left, ~300mm wide × **200–220mm deep — not the full box depth**; a fixed top strip behind the hinge line keeps open height to ~400–415mm total under kitchen cabinets, and gives the hinge + vent somewhere solid) carries only the lid display on its inner face (the 10.1" panel module ≈ 235×161mm fills a 300×220 lid like a framed picture; 10.1" is the size ceiling before the box must grow). Closed = glass protected facing down; open = counter viewing angle. Service lid (right, thin flap) flips up over the printer bay for roll changes (~monthly). The **slot is cut into the fixed top panel** at the bay's front edge — not into the service lid, so slot alignment never depends on the lid seating.
- **Lid settles at one angle: ~70° from horizontal** (Nest-Hub-style ~20° lean-back, right for counter height viewed standing). Mechanism: exposed brass butt hinges + a **brass chain or leather strap** that goes taut at 70° — one position, zero mechanism, period-correct. Upgrade option if two positions prove wanted: a notched **quadrant stay** (~55° looking-down + ~75° across-the-room).
- **Deck sits at ≈ printer-top height** (~160mm), recessed 35–40mm below the ~205mm rim — one box height outside, sunken control deck inside. The ~140mm clear cavity _under_ the deck is the equipment bay, and the **fit check passes with ~75mm to spare**: deepest deck protrusions (arcade button ~40mm, pot bodies ~30–40mm; the deck screen mounts proud, only cables pass through) reach down to ~120mm above the floor, while the Pi 5 + Active Cooler stands only ~30mm (≈45mm on standoffs). Layout: powerboard + both plug-packs along the back wall (the official Pi PSU is wall-plug style — it hangs off the powerboard, it doesn't lie flat), Pi on the floor beside the vent grille, Pico on the deck's underside beneath the dials, speakers low at the front. **Service access: the deck panel screws down with exposed brass screws and lifts out as one wired harness** — unscrewing it is how the box opens for surgery (alternative: removable base). If the exposed-Pi look is still wanted, it's a mesh/glass window in the equipment-bay side wall, not deck space.
- **Deck is recessed below the box rim** by 30–40mm so the lid closes flat over wooden knobs and toggle bats (easier to build than a tray-lid, and the rim shields the controls). Spare deck space earmarked: an **analog needle meter** (PWM ≥1kHz from the Pico + smoothing cap — minutes-to-bus or today's max temp), a **pencil groove + tear-off zone**, a **mic + push-to-talk spot reserved for Phase 3 voice** (drill now, fill later — the speakers live on the front face, see below), brass CHOTA nameplate. **Wood-thickness gotcha (find out before cutting the nice wood):** pot/toggle bushings carry only 6–8mm of thread — counterbore each mount from the rear with a Forstner bit down to a 4–5mm skin, or inset a 1–2mm aluminium sub-panel. Wire the harness in **JST-XH, not Dupont** (Dupont loosens in a box that gets moved).
- **Paper exits the top; printer sits flat on the box floor** — dead-straight path, toast-pop theater, and the top is where roll-change access lives anyway. (The MUNBYN _does_ advertise wall-mount support, so a front-exit vertical mount à la paper-console is viable — considered, not chosen.) **Auto-cutter caveat:** a cut sheet stands loose in the slot, and the 06:45 prints several briefs in sequence — either add a small catch tray beside the slot or skip auto-cut for the morning batch. Test with the real printer before cutting wood. **Slot detail (field research):** thermal paper curls toward its printed face — fit a 10–15° outward-angled guide at the slot so the leading edge can't fold back in and jam the next print; slot width ≥4mm. **Paper:** switch to phenol-free 80mm rolls (Blue4est or ascorbic-acid developer, ~20% premium) before kids handle paper daily, and buy rolls with an end-of-roll indicator stripe. Vent the printer bay too — heat slowly pre-activates thermal coating (grey backgrounds).
- **Pi = server + both screens; Pico = the entire control surface.** With the lid going LCD (below), the Pi's 40-pin GPIO header is **completely free again** — no HAT, no through-hinge SPI jumpers. The through-hinge cable is now the lid panel's **DSI FFC**, and the strain-relief rules still apply: route along the hinge axis with 6–8cm of slack so it bends on a large radius on every open/close, never at the connector; FFCs have finite flex cycles, so leave a generous service loop. All dials/toggles/button/LEDs go to the Pico, which connects to the Pi by one USB cable (data + power) — udev rule pins it to a stable `/dev/ttypico`, JSON-lines protocol (debuggable with `cat`), and a two-sided watchdog (Pico self-resets if the host goes quiet; host re-opens when the tty reappears) so reboots/deploys never wedge it.
- **Lid display — re-decided June 2026: Waveshare 10.1" DSI LCD (C)** (Core Electronics $129.95, 1280×800 IPS landscape-native, bare-PCB look; + 22→15-pin FPC adapter ~$5–10). The **literary clock** flipped this from e-ink: per-minute content is physically impossible on Spectra 6, `/clock` already exists, and the panel is bigger _and_ cheaper than the Inky. **Verified sysfs backlight 0–255** (`dtoverlay=vc4-kms-dsi-waveshare-panel,10_1_inch`; `echo N > /sys/class/backlight/*/brightness`) → an evening-dim + night-off schedule job is the contract that keeps this from becoming the ignored glowing dashboard again. Theme it warm/dark sepia. **HDMI panels are disqualified for the lid:** `ddcutil setvcp` (DDC/CI brightness write) is broken on Pi 5 Bookworm (open bug, ddcutil #356) and budget panels — including the considered GeeekPi 7" — have OSD buttons only. Fallback pick: official Touch Display 2 7" ($106, first-party sysfs, smaller + chunkier bezel). Mounting rules unchanged: routed rebate, panel held by its edges, anti-glare surface or film.
- **Dual-screen config: both panels on DSI** — the Pi 5 has two 22-pin CAM/DISP connectors (deck 5" on one, lid 10.1" on the other; forfeits a camera port, fine). This sidesteps an active kernel bug (raspberrypi/linux #7041: an active DSI panel makes HDMI outputs vanish under labwc). Per-output kiosk window placement under labwc is reported flaky — **test on arrival; the documented reliable fallback is X11 + two Chromium windows with `--window-position`**.
- **E-ink: deferred, not dead.** The Inky Spectra 6 ($150.40 at Pi Australia, currently backordered) lost to the LCD on price, size, and the clock. Its niche — zero-glow paper look, battery-powered Pico satellites elsewhere in the house — can return later; the hard-won Spectra 6 knowledge (20–25s real refresh, no partial refresh, palette-snap-text/Atkinson-photo dithering, FPC handling) is preserved in [`inspiration.md`](inspiration.md) §Field notes.
- **Speakers:** two small 2" full-range drivers behind brass-mesh grilles, low on the front face. **The Pi 5 has no headphone jack** — drive them via a USB audio dongle + PAM8403-class amp (~$15 total; I2S works but is fiddlier alongside the Inky ribbon). Drill the grilles + mount the drivers at build time, wire them in Phase 3 (voice).
- **Size — measure the actual MUNBYN before cutting wood.** Amazon AU claims 164W × 286D × 160H mm, but listing dims are often the shipping box (this printer class usually runs ~220mm deep). Working envelope: **~480–500W × 260–330D (set by the measured printer) × 200–210H mm external**. Printer bay ≈ 185mm of width (right third); screen/deck zone ≈ 300mm (left two-thirds — frames the 174mm-wide Inky with good margins); height = printer 160 + floor clearance + top panel. Vintage-radio proportions. Single power inlet → internal powerboard feeding the Pi PSU + printer PSU. Vent grille near the Pi (Active Cooler needs airflow). Toolbox latches, maybe a recessed handle.

**The interaction loop:** turn the WHO dial (family member), turn the WHAT dial (today / joke / puzzle / …), tiny screen shows the selection, smack the big red PRINT button, printer chunk-chunks. No app, no login, kid-operable.

**Parts on hand (June 2026 order):** Pico 2 WH, 2× 10k linear panel-mount pots (¼" shaft — custom wooden knobs go on these), 1× encoder module with button (bake-off vs the pots: pot = end-stops + labeled positions painted on the wood; encoder = detent clicks + needs the screen to show selection), 3× mini SPDT toggles, 1× chunky SPST toggle (missile-switch cover compatible — cover not bought yet), 30mm red LED arcade button, 25× 10mm diffused LEDs (**need current-limiting resistors, not bought yet**), brass M2.5 standoffs, breadboard + M-M/M-F/F-F jumpers. **Deck screen — decided June 2026: a 5" Pi-driven bare-PCB panel, dials grouped around it, OFF by default.** The screen lies flat on the deck, so it's not a thing you watch — it's part of making the dials feel alive: **dark until a knob turns or the lid opens, then awake for a few minutes** (dial reactions, story-generation animation, the literary clock as the awake-idle face), then back to dark. Pico → server → SSE → a themed `/panel` Svelte route in a Chromium kiosk. Fine-grained dimming was dropped in favour of hard off/on (June 2026, after the bezel/aesthetic re-think). Implementation notes:

- **Aesthetic is a hard criterion: bare PCB, no consumer bezel.** This **disqualified the official Touch Display 2** — measured ~14–17mm of chunky plastic bezel on every side (active area is only 110×62mm of a 143×91mm slab). The raw Waveshare/Freenove boards — toughened glass face, exposed PCB back, visible FPC — _are_ the exposed-electronics look. Mount proud on brass standoffs, ribbon visible.
- **Candidates (researched June 2026, Sonnet fan-out):** ① **Waveshare 5" DSI LCD (B) low-power** — **the pick**: Core AU $69.95 in stock, 800×480 IPS landscape-native (same grid as the Inky), bare PCB + tempered glass, documented `/sys/class/backlight` (brightness 0–255 + `bl_power`). ② **Waveshare 5" DSI LCD (C)** — 1024×600, same raw look, ~US$55 but no AU stockist (Amazon AU/PiShop) — the sharper-screen upgrade if shipping wait is fine. **Either Waveshare: must be a Rev2.2 board** — earlier revisions trip the Pi 5's short-circuit detection and won't power up. ③ **Freenove FNK0078** — raw green PCB, Amazon AU ~$55, but backlight control undocumented and the Pi 5 adapter cable is NOT in the box. ④ **DFRobot DFR0550-V2** — borderless laminated matte, 4.9mm thin, *includes* the Pi 5 cable, US$49.90, but no AU stockist. **Gotcha for all non-official panels: the Pi 5's DSI port is 22-pin; these boards are 15-pin — add a 22→15-pin adapter cable (~$5) to the order.** **Ruled out:** TD2 (bezel), HyperPixel (DPI eats all 40 GPIO — conflicts with the Inky ribbon), HDMI panels (two cables, no backlight control), SPI (too slow). Touch present on all — leave unconfigured.
- **Off/wake mechanics (research finding — don't trust DPMS):** `wlr-randr --off` / compositor DPMS blanks the image but **leaves DSI backlights glowing** (long-standing Pi firmware gap). The reliable off is a sysfs write: `echo 0 > /sys/class/backlight/*/brightness` (plus `bl_power` where present), granted via a narrow sudoers entry and called by the panel listener — wake on any Pico event, sleep on a 3–5min idle timer. If the Waveshare's minimum brightness leaves a faint glow, the documented fix is swapping the BL resistor 100K→68K (a one-joint solder job, perfectly on-theme). For later wake-on-approach: **LD2410 mmWave on the Pico's UART, not PIR** (PIR goes blind on a person standing still); needs per-gate threshold tuning in engineering mode first — kitchen fans and fridge compressors false-positive on defaults.
- **Kiosk stack is an apt-install, not a reflash:** keep OS Lite; when the screen lands: console-autologin → **labwc** (research verdict: Pi OS's own compositor with the documented kiosk path; `cage` fights XDG_RUNTIME_DIR/root when systemd-launched) → Chromium as a user service with `Restart=always` and `--kiosk --ozone-platform=wayland --noerrdialogs --no-first-run --disable-session-crashed-bubble --disk-cache-dir=/dev/null`. Add a **nightly restart timer** (long-running kiosk Chromium leaks RAM over 2–3 days). The `/panel` page reloads itself on an SSE `deploy` event the server emits at boot — fresh UI after every `npm run deploy`. (`--kiosk` blocks DPMS, which doesn't matter — our off-switch is the backlight sysfs write.)
- **Touch stays off.** The screen displays; the brass controls control — touch would cannibalize the dials.
- Mount on a **swappable sub-panel** (small plate screwed into a deck opening) so screen upgrades never mean rebuilding the deck.
- The already-owned **Pico Display Pack 2.8"** is demoted to the drawer; the Pico is now a pure input device (no Omnibus needed). **No soldering iron yet** — breadboard-prototype first, lay out the box, then solder.

**Power budget (all fine on the official 27W PSU):** Pico ≈ 50mA off one Pi USB port; deck 5" ≈ 0.5A; lid 10.1" ≈ 0.7–1A — check the 10.1"'s power feed on its wiki (larger DSI panels often take 5V from the GPIO header or USB, not just the FFC; the header is free now). The Pi allows 1.6A across USB on the official supply and dual displays are trivial compute (it drives dual 4K). The printer, the only real power hog, has its own brick.

### Devices all speak HTTP — the one architecture rule

Every physical device is a dumb client of the chota server. No device-specific logic in the server beyond a route.

- **Controls → server:** the panel controls fire `POST /api/print/[kind]` — the route that already exists and already drives every print. Whether the dials hang off the Pi's own GPIO (a small script POSTing to `localhost:8000`) or off the Pico (POSTing over Wi-Fi, or USB-serial into the Pi) is an implementation detail the server never sees.
- **Pico owns analog.** The Pi 5 has **no ADC** — the pots can only be read by the Pico (3 ADC pins). Toggles/buttons/encoder are digital and work on either. The Pico also drives the tiny selection screen. A Pico over USB is also a fine "GPIO co-processor" (power + rock-solid serial in one cable, Wi-Fi unused).
- **Displays ← server:** both box screens are just Chromium kiosk windows on chota routes — the lid shows `/clock`, the deck shows `/panel`. And the print pipeline already renders any person's brief as a server-side PNG at a fixed pixel width (the agent-browser screenshot of `/print/[who]`), so a _deferred_ e-ink client — battery-powered Pico 2 W + small panel that wakes, fetches a pre-dithered PNG from an `/eink/[who].png` route, displays, deep-sleeps — stays dumb too. **The hard part is already built.**

### What this leans on (already shipped)

- `POST /api/print/[kind]` — print any format on demand; the panel button is just a new caller.
- `/print/[who]` rendered bare + screenshot → PNG → `printPng()` — the server-side-image pipeline e-ink reuses.
- `defineJob()` cron system, `/admin/jobs`, `/api/health` — the ops surface a headless box needs.
- Deploy + `chota.service` are box-agnostic by design.

## Software shortlist

Roughly in order. The audit's "Highest Leverage" list, plus what the hardware direction adds:

1. **Panel control listener** — read encoder/pot + button (Pico), POST to `/api/print/[kind]`; dial-state events also feed the `/panel` deck-screen route (SSE) once the 5" screen lands. First new code the hardware needs; tiny. _Engineering crib (field research):_ pots — analog ground to the Pico's AGND pin, 8–16-sample averaging, and dead-band hysteresis per position bucket (without it the selection flickers at bucket boundaries); encoder — gray-code transition table plus a 1kΩ/22nF RC filter on CLK/DT (software debounce alone misses sub-interrupt-latency bounce).
2. **More on-demand print formats** — the WHAT dial needs positions: `today`, `joke`, `puzzle`, `shopping`, `cal`. Mostly exists as composers; fill the gaps. **Pre-generate + cache** (the strongest product finding in the field research): render briefs overnight and serve the cached PNG on button press in <5 seconds — _press → paper-in-hand_ is the whole ritual, and every surveyed project that generated at press time lost the kids during the wait. Only the `story` format generates live, where the wait is the theater.
3. **`story` print format — the dial-combination feature.** WHO dial × genre dial (positions parent-curated in `chota.config.ts`: space, dinosaurs, mystery, …) × a length switch → `POST /api/print/story` → Haiku writes ~300 words starring the dialed kid → paper. Free-text never enters; the dials constrain the prompt space, so it's kid-safe by construction. The 5–15s generation time is what the deck screen's animation is for.
4. **Tomorrow-prep print** (evening) — first event, gear, bins, weather. (audit §Highest Leverage)
5. **School holiday / pupil-free suppression** — don't print bus/class sections on non-school days.
6. **Rain-at-pickup signal** — "umbrella for pickup" beats generic weather.
7. **Sentral cookie freshness in `/admin`** — the known silent-failure path.
8. **Lid screen bring-up** — second DSI output showing `/clock` in its own kiosk window (test labwc dual-output against kernel bug #7041; X11 + `--window-position` is the proven fallback) plus a **backlight-schedule job** (evening dim, night off — sysfs writes via the same sudoers-gated helper as the deck screen). _(Deferred e-ink path, if it ever returns: `/eink/[who].png` + a stateless `uv run` push script with [pimoroni/inky](https://github.com/pimoroni/inky) — no Python server, per plan.md's `py/`-scratchpad rule.)_
9. **Agent closing line** on the morning brief — the bounded Phase 2 agent job (ToolLoopAgent is already wired).

Explicitly **not** next: kiosk-mode polish, night-dimming, dashboard widgets, generic chat surface.
